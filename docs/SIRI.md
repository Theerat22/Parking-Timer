# ตั้งค่า Siri ผ่าน Apple Shortcuts

ต้องมีเว็บ HTTPS ที่เชื่อม Supabase แล้ว เริ่มจากแท็บ Siri → สร้างโทเคน คัดลอกเก็บไว้ โทเคนแสดงเต็มเฉพาะตอนสร้างและใช้ได้เฉพาะคำสั่งจอดรถ ห้ามใช้ Supabase service role key แทน

ชื่อ action ใน Shortcuts อาจต่างกันตามภาษาและเวอร์ชัน iOS ด้านล่างใช้ชื่อภาษาอังกฤษเพื่อค้นหาได้ง่าย

## 1. “ฉันมาจอดรถแล้ว”

1. เปิดแอป Shortcuts กดสร้างคำสั่งใหม่ ตั้งชื่อ **ฉันมาจอดรถแล้ว**
2. เพิ่ม **Generate UUID** แล้ว **Set Variable** ชื่อ Request ID หากเครื่องไม่มี Generate UUID ให้ใช้วันที่ปัจจุบันที่จัดรูปแบบ `yyyyMMddHHmmssSSS` รวมกับเลขสุ่มยาว เพื่อให้ได้ค่าอย่างน้อย 16 ตัวอักษร ใช้เฉพาะตัวอักษร ตัวเลข _ และ -
3. เพิ่ม **URL** ใส่ `https://YOUR_DOMAIN/api/parking/start`
4. เพิ่ม **Get Contents of URL** เปิดรายละเอียด ตั้ง Method เป็น **POST**
5. ใส่ Headers:

| Key | Value |
| --- | --- |
| Authorization | `Bearer YOUR_SHORTCUT_TOKEN` |
| Idempotency-Key | ตัวแปร Request ID จากข้อ 2 |

ไม่ต้องส่ง Request Body แทน YOUR_DOMAIN และ YOUR_SHORTCUT_TOKEN ด้วยค่าจริงของคุณ ไม่ใส่โทเคนใน URL

6. เพิ่ม **Get Dictionary Value** อ่าน `ok` จากผลตอบกลับ
7. เพิ่ม **If** ถ้า ok เป็น true ให้ **Get Dictionary Value** อ่าน `message` จากผลตอบกลับเดิม แล้ว **Speak Text** ข้อความนั้น
8. ใน Otherwise ใช้ Speak Text ว่า **ยังยืนยันการบันทึกไม่ได้ กรุณาตรวจสอบในเว็บ**
9. ทดสอบด้วยปุ่มเล่น ยอมรับสิทธิ์เข้าถึงโดเมนเมื่อระบบถาม แล้วดูหน้าเว็บว่ามีรายการที่กำลังจอดจริง
10. เรียก Siri แล้วพูด **ฉันมาจอดรถแล้ว**

## 2. “ออกจากที่จอดรถแล้ว”

ทำซ้ำขั้นตอนเดิม ตั้งชื่อ **ออกจากที่จอดรถแล้ว** และเปลี่ยน URL เป็น:

`https://YOUR_DOMAIN/api/parking/stop`

ใช้ POST และ Generate UUID ใหม่ต่อการเรียกคำสั่งหนึ่งครั้ง Headers และการอ่านข้อความเหมือนข้อแรก

## 3. “ค่าจอดรถเท่าไหร่”

สร้างคำสั่งชื่อ **ค่าจอดรถเท่าไหร่** ตั้ง URL เป็น:

`https://YOUR_DOMAIN/api/parking/status`

ใช้ Method **GET** และ Authorization header เท่านั้น ไม่ต้องมี Idempotency-Key จากนั้นตรวจ ok และอ่าน message เหมือนเดิม

## เมื่อเครือข่ายมีปัญหา

ห้ามตั้ง Speak Text เป็นข้อความสำเร็จตายตัว ต้องอ่าน message หลังจากได้ `ok:true` เท่านั้น คำสั่ง Get Contents of URL บางเวอร์ชันหยุด Shortcut ทันทีเมื่อเครือข่ายล้มเหลว จึงอาจไม่วิ่งถึง Otherwise และไม่สามารถรับรองว่าจะอ่านข้อความ fallback ทุกครั้ง หากเห็น network error หรือ Shortcut หยุด ให้ถือว่ายังยืนยันไม่ได้ แล้วตรวจในหน้าเว็บ

หากออกแบบเมนู retry ในการเรียกครั้งเดียวกัน ให้ใช้ Request ID เดิม อย่าสร้าง UUID ใหม่ภายในรอบ retry หากกดรัน Shortcut ใหม่จะเป็นคำขอใหม่ ให้ตรวจ status ก่อนโดยเฉพาะเมื่อมีการเริ่มจอดรอบใหม่จากอุปกรณ์อื่น

ผลลัพธ์เริ่มซ้ำจะรักษาเวลาเดิม หยุดขณะไม่มีรายการจะบอกว่ายังไม่มีรายการ ส่วนคำขอ stop เดิมที่ส่งซ้ำด้วย key เดิมจะคืนผลเก่าและไม่ปิดรายการใหม่

## ตรวจบน iPhone จริง

- ทดลองเริ่ม ตรวจสถานะ และหยุด โดยดูผลในเว็บทุกครั้ง
- ปิด Safari แล้วเรียกคำสั่ง ตรวจว่าประวัติยังตรงกัน
- ทดลองขณะล็อกเครื่อง บางคำสั่ง/การตั้งค่าอาจต้องปลดล็อก
- ตั้งภาษา Siri ให้รองรับชื่อคำสั่งภาษาไทย หาก Siri ตีความผิด ให้เปลี่ยนชื่อเป็นวลีที่เรียกได้ชัดขึ้น
- เพิกถอนโทเคนจากเว็บ แล้วตรวจว่าคำสั่งเดิมไม่สำเร็จ
- โทเคนที่มี last_used_at หมายถึงระบบได้รับคำขอที่ยืนยันตัวตนด้วยโทเคนนี้ ไม่ได้พิสูจน์ว่า Siri ออกเสียงหรือทำงานขณะล็อกได้

คู่มือนี้ตรวจจากเอกสาร Apple แล้ว แต่ยังไม่ได้ทดสอบ Siri บน iPhone จริง และไม่มีลิงก์ติดตั้ง Shortcut ที่อ้างว่าพร้อมใช้งาน

แหล่งอ้างอิง:
- [Request your first API](https://support.apple.com/guide/shortcuts/request-your-first-api-apd58d46713f/ios)
- [Use Siri to run shortcuts with your voice](https://support.apple.com/guide/shortcuts/run-shortcuts-with-siri-apd07c25bb38/ios)

## ข้อความสำหรับอ่านออกเสียง

คำสั่งทั้งสามอ่านฟิลด์ `message` เดิมได้ ไม่ต้องแก้ Shortcut หลัง deploy โค้ดใหม่ ข้อความใช้คำเต็ม เช่น:

- เริ่มบันทึกเวลาจอดรถแล้ว เวลา 8 นาฬิกา 30 นาที
- จอดไป 4 ชั่วโมง 15 นาที ค่าจอด 60 บาท
- สิ้นสุดการจอดแล้ว รวม 2 ชั่วโมง 1 นาที ค่าจอด 0 บาท 33 สตางค์ (รายการเดิมที่ใช้กติกาตามนาที)

หน้าเว็บยังแสดงเวลาแบบกระชับได้ การปรับนี้เปลี่ยนเฉพาะข้อความตอบกลับของ API สำหรับเสียง
